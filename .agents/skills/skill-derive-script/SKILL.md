# SOP

## Phase 1 -- 定位腳本抽取點

1. `READ` 使用者需求、目標 Skill 的 `SKILL.md`，以及指定步驟已使用的既有腳本（若有）。
2. `CHECK` 使用者指定的 Phase 與步驟可在目標 SOP 中唯一定位；無法唯一定位時，停止並請使用者補充。
3. `READ` 分析指定步驟時，讀取 `rules/腳本抽取分析-格式規範.md` 的所有 Rule，建立腳本抽取分析檢查清單。
4. `THINK` 依已載入的腳本抽取分析檢查清單，分析指定步驟的輸入、可觀察的輸出、完成條件與執行時的副作用，判斷可委派給 Python 腳本的工作範圍。
5. `CHECK` 逐條驗證腳本抽取分析檢查清單；未通過時修正腳本職責，無法修正時停止抽取。
6. `THINK` 依已確認的腳本職責，設計腳本的檔名、命令列參數、依賴、Python 版本要求，以及目標 SOP 的委派與驗證步驟。

完成條件：腳本抽取分析檢查清單均已通過，且已定位目標步驟，確定腳本職責、執行介面與目標 SOP 的修改範圍。

## Phase 2 -- 提出 Before／After

1. `WRITE` 向使用者展示原始 SOP 片段、修改後 SOP 片段，以及預計建立或修改的腳本路徑、命令列介面、Python 版本要求、依賴、副作用與執行結果。
2. `CHECK` 使用者回覆；要求修改時返回 Phase 1，未明確確認時停止執行。

完成條件：使用者已明確確認 Before／After 與腳本設計。

## Phase 3 -- 寫入與驗證

1. `READ` 委派腳本與 SOP 寫入時，讀取 `rules/腳本委派-格式規範.md` 的所有 Rule，建立腳本委派檢查清單。
2. `CHECK` 已確認的提案符合腳本委派檢查清單；未通過時返回 Phase 2。
3. `DELEGATE` 依已確認的腳本設計與腳本委派檢查清單，使用 `skill-form-script` 建立或更新目標 Skill 的 Python 腳本。
4. `DELEGATE` 依已確認的 After 與腳本委派檢查清單，使用 `skill-form-sop` 更新目標 `SKILL.md`，以 `DELEGATE` 步驟執行腳本，並加入必要的結果驗證。
5. `CHECK` 逐條驗證腳本委派檢查清單，確認腳本與目標 SOP 符合已確認的 Before／After，原有流程目的與順序未被非必要改變，且受影響的 Skill 通過適用驗證。

完成條件：腳本委派檢查清單已通過，腳本與目標 SOP 均已寫入，且已確認的修改及所有適用驗證均已通過。
